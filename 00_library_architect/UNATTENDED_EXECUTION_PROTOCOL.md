# Trae 无人值守执行协议

版本：1.0.0  
目标根目录：`D:\00_skiill_ku`  
配套 Skill：本包中的 `SKILL.md`

## 0. 授权范围与执行目标

用户要求 Trae 在用户暂时离开电脑期间，完成个人 AI 技能库审计、重构、必要的本地依赖准备和测试。用户尚未将 Personal AI Skill Architect 安装到技能库，因此本协议要求 Trae **先将本包内的 `SKILL.md` 安装到目标目录，再依据该 Skill 执行**。

本协议授权范围：

- 读取和审计 `D:\00_skiill_ku`。
- 在修改前备份目标目录内将被修改的文件。
- 在 `D:\00_skiill_ku` 内创建目录、文档、脚本、测试数据和报告。
- 对目标目录内现有技能进行可回滚的增量修改。
- 在专用项目虚拟环境/本地依赖目录中安装必要、可信、非付费的依赖，前提是先检查来源、许可证和安装脚本风险。
- 使用公开、无需登录且允许访问的测试资源进行低频测试。
- 对用户已配置且当前可用的工具进行只读健康检查；不得输出凭据。
- 对无法访问的外部服务记录 BLOCKED，并继续其他阶段。

本协议**不授权**：

- 删除原始文件、仓库、数据库、素材或浏览器运行时。
- 对外公开发布视频、帖子、评论、飞书消息或其他内容。
- 购买服务、充值、启用付费套餐或产生新的费用。
- 新建账户、完成 OAuth 授权、修改/轮换/展示 Token、Cookie、密码或 API Key。
- 未备份就修改 Trae/WorkBuddy/Loomi 等客户端的活动全局配置或覆盖现有 MCP 配置。
- 将用户素材、私人文件或账号数据上传给第三方服务。
- 安装来源不明的脚本、可执行文件或扩展。
- 绕过登录、付费墙、访问控制、验证码或安全防护。

如操作超出以上范围，记录为 `BLOCKED: NEEDS_USER_APPROVAL`，不要反复询问或停止其他任务。

## 1. 重要运行前提

“无人值守”不代表 Trae 一定能在客户端关闭、会话过期、电脑睡眠、断网或系统重启后继续运行。开始前必须检查并在报告中记录：

- Trae 是否仍处于可执行 Agent 的会话中。
- 文件系统和终端工具是否可用。
- 是否有连续执行/命令超时限制。
- Windows 是否可能休眠或锁屏后中断任务。
- 当前磁盘空间是否足够。

**不得自行更改 Windows 电源策略、关闭安全软件或修改系统级设置以维持运行。** 若运行环境会在用户离开后中断，应完成当前可执行部分、保存检查点，并准确报告中断条件；不得声称能够在会话终止后后台继续。

## 2. 总控行为：不等待用户的安全决策矩阵

| 情况 | 无人值守处理 |
|---|---|
| 本地文档缺失、路径错误 | 记录，寻找实际目录/同类文件；不猜测，不覆盖 |
| 缺少 Folo/Reddit 凭据 | 标记 BLOCKED，继续 GitHub、公开 RSS/网页等可用来源 |
| MCP 配置存在但无法连接 | 保存脱敏错误，查明原因；不修改活动配置 |
| 需要付费 API 或付费下载 | 不开通，使用免费/本地替代或标记阻塞 |
| 需要登录/OAuth | 不代用户授权，记录需要用户完成的步骤 |
| 需要修改活动客户端配置 | 生成候选配置、差异和备份恢复说明，不应用 |
| 需要公开发布/发送消息 | 只生成预览、草稿或 dry-run，不提交 |
| 需要上传用户媒体到第三方 AI | 使用本地工具或合成样本；未获授权不上传 |
| 依赖安装需要管理员权限 | 不提权；尝试项目级隔离环境，否则记录阻塞 |
| 外部依赖安装脚本来源不可信 | 不执行；检查替代来源 |
| 某一服务故障 | 标记该服务，继续不依赖它的任务 |
| 测试失败 | 保存日志，定位修复；最多进行有限次数修复，不无限循环 |
| 删除、清空、覆盖不可恢复内容 | 禁止；创建新文件或备份版本替代 |

## 3. 执行顺序与检查点

### 3.1 建立工作目录

在目标根目录内创建或复用：

```text
D:\00_skiill_ku\
├── 00_library_architect\
│   ├── SKILL.md
│   ├── UNATTENDED_EXECUTION_PROTOCOL.md
│   └── START_HERE_FOR_TRAE.md
├── _backup\
├── _logs\
├── _reports\
└── ...现有技能库，不移动、不删除...
```

如果目录已经存在，先比较文件；不得覆盖更新版本。安装本包中的 Skill 时，若目标 `SKILL.md` 已存在，先备份，再做内容合并或创建带版本号的新副本。

### 3.2 记录检查点

每个 Phase 开始和结束时更新：

- `_reports/EXECUTION_STATUS.md`
- `_reports/PHASE_CHECKPOINTS.md`
- `_logs/<timestamp>/execution.log`
- `CHANGELOG.md`（若根目录尚无则创建）

记录当前阶段、已完成项、未完成项、修改文件、测试命令、结果、备份位置和恢复方法。日志必须脱敏。

### 3.3 执行 Phase 0～7

严格依照配套 `SKILL.md` 的 Phase 0～7 顺序执行：

0. 环境确认、审计与备份。
1. 整理共享爬虫技能库。
2. 重构视频素材发现、参考视频分析、剪辑和发布 Skill。
3. 重构 TechRadar 和情报数据库设计/实现。
4. 建立跨客户端能力注册表与适配文档。
5. 抽取共享服务并完成集成。
6. 执行测试和修复。
7. 生成最终交付报告。

每个 Phase 完成后必须保存检查点。若 Trae 或电脑意外中断，重新启动时先读取 `EXECUTION_STATUS.md` 和 `PHASE_CHECKPOINTS.md`，从最后一个**已验证通过**的检查点恢复，不得盲目重复安装或覆盖文件。

## 4. 依赖安装规则

1. 优先复用机器上已存在的工具和版本。
2. Python 使用项目级 `.venv`；Node 使用项目本地依赖，不执行全局安装。
3. 安装前检查官方来源、许可证、维护状态、依赖树和安装命令。
4. 固定可复现版本，保存 `requirements.txt`、锁文件或安装清单。
5. 不执行远程下载后立即运行的管道命令，不运行未经检查的 `install.ps1`、`curl | iex`、`npm exec` 外部未知脚本等。
6. 如需下载二进制，优先官方 Release，验证签名/哈希（若官方提供），并记录来源。
7. 需要管理员权限、驱动、系统服务、浏览器扩展或全局环境修改时停止该项，记录阻塞。
8. 每个新增依赖都要说明由哪个 Skill 使用、替代方案是什么、如何卸载。

## 5. 对不同系统的实际测试方式

### 爬虫/素材采集

- 使用公开测试网页或本地 HTML fixture 测试解析。
- 使用授权、可下载的公开测试媒体或自生成媒体文件测试下载/解码。
- 测试文件 SHA256、元数据、去重、超时、重试上限和断点状态。
- 遇到登录墙、访问控制或验证码时停止，不尝试绕过。

### 视频生成

- 使用本地生成的短测试视频、图片、音轨和字幕作为 fixture。
- 测试 FFprobe 元信息读取、FFmpeg 渲染和 QC。
- 若有用户授权提供的参考视频，可在本机分析；不得擅自上传外部服务。
- 可验证素材搜索流程，但不得将授权未知的素材用于正式作品。
- 发布仅做 dry-run/草稿预览；不公开发布。

### TechRadar

- 首先测试 Folo、Reddit 和 GitHub 的可用状态。
- 只读取实际授权且接口允许访问的内容。
- 分别记录标题扫描、正文读取、评论读取和深入研究数量。
- 无凭据时，使用已配置的公开信息源开展降级测试，并明确标注它不等同于用户 Folo/Reddit 订阅。
- 通过同一 URL/内容哈希重复采集，验证数据库去重。
- 情报输出必须带来源 URL 和发布时间；无法核实日期的内容标记未知。

### 跨客户端迁移

- 校验 YAML/JSON 文件格式。
- 为 Trae、WorkBuddy、Loomi、Claude Code 和通用 MCP Agent 生成适配说明。
- 在不覆盖真实配置的前提下，使用临时配置验证格式或 MCP 启动命令。
- 对客户端功能差异标注“已验证”“基于官方文档”“待实测”。

## 6. 测试质量门禁

每项测试必须记录：

- 测试 ID 和目标。
- 测试环境及依赖版本。
- 输入 fixture 或数据来源。
- 实际执行命令。
- 实际退出码。
- 关键输出或生成文件。
- 预期与实际是否一致。
- 状态：`PASS` / `PARTIAL` / `BLOCKED` / `FAIL` / `NOT_TESTED`。

有以下情况才可标记 PASS：

1. 命令/工具实际执行。
2. 输出文件或数据真实存在。
3. 核心字段或媒体可解析。
4. 结果符合明确的预期。
5. 日志和证据可复查。

只生成配置、只通过语法检查、只看到工具列表，不足以标记业务能力 PASS。

## 7. 修复和重试规则

- 普通测试失败：先读取日志、定位根因，再进行最多 2 轮有明确变化的修复。
- 认证失败：不自动重试凭据、不猜 Token、不更改凭据。
- 网络失败：有限重试并设置退避；不循环请求。
- 安装失败：记录环境、错误和回滚方式，换用安全的可用替代方案。
- 同一问题连续两轮修复仍失败：停止该分支，标记 FAIL/BLOCKED，继续其他工作。
