# 进阶能力升级方案（Phase 5）

## 1. 现状与差距

| 能力 | 现状（实测） | 差距 | 优先级 | ROI |
|---|---|---|---|---|
| 页面形态判定 | `probe_site` 可判定 SSR/SPA/阻断 | 尚未接入主采集器自动路由 | P0 | 高：避免对空壳无效解析 |
| 正文抽取 | 三引擎可降级 | 默认仍走内置兜底，未装 trafilatura | P1 | 高：正文质量直接决定情报价值 |
| 登录态采集 | 可判定，但本机 profile 未登录/触发风控 | 需用户手动登录；不能代登录 | P1 | 中：平台深度内容的主要入口 |
| 平台适配 | B 站公开 API 可用；抖音需签名；小红书需渲染 | 缺平台专用适配器 | P2 | 中：按需扩展，不做全平台承诺 |
| 渲染取证 | Playwright 可用（Chromium 151） | 缺"渲染前后对比 + 截图存证"流程 | P2 | 中：便于排障与合规审计 |
| 采集编排 | 单工具可用，未串成流水线 | 缺 `discover → probe → route → extract → store` 一键编排 | P2 | 高：减少人工拼接 |
| 反爬对抗 | 只识别、不破解 | **这是设计原则，不是差距** | - | - |

## 2. 建议实施顺序

### P0（已在本次完成）
1. 探测画像与兼容矩阵。
2. 登录态安全边界（授权、不导出、遇验证即停）。
3. 抽取三引擎降级。
4. 主题情报补采（把外部技术发现注入 TechRadar）。

### P1（下一轮，约 1 个工作日）
1. 在 `material_crawler` 中加入 `--auto-route`：先 probe，再按 `render_layer` 选静态/浏览器。
2. 把 `probe_logged_in` 的判定接入采集前置检查，未登录时直接降级为公开路径。
3. 为 Bilibili 增加专用适配器（热门/详情/公开字幕可用性探测）。

### P2（按需）
1. 小红书渲染后字段映射（仅用户已登录且无验证时）。
2. YouTube player 响应解析（仅公开视频的基础元数据）。
3. 渲染取证截图 + DOM 快照归档。

## 3. 验收标准（可测）

| 能力 | 验收 |
|---|---|
| 自动路由 | 对 SSR 站点不启动浏览器；对 SPA 站点启动浏览器；两条路径都有产物 |
| 登录态 | 未登录时明确 `LOGGED_OUT`，不产生"伪登录"数据；遇验证码 0 次绕过尝试 |
| 抽取 | 三站点正文 ≥200 字符，且输出标明实际引擎 |
| 平台适配 | B 站 API 返回 code=0 且字段完整；失败有明确错误码 |
| 编排 | 一条命令产出 `manifest.json` + 正文 + 入库计数 |

## 4. 风险

- 平台风控策略随时变化：所有结论都带 `checked_at`，过期需重测。
- 登录态涉及用户隐私：只在本机使用，禁止上传、禁止写入报告。
- 新增依赖必须可选：缺失时主流程可用。
