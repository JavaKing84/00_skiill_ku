# 🛠️ Skill 01: 反爬侦察与破局 SOP

> 通用宏观方法论。先定性，再选武器，最后才写代码。
> **所属阶段**：P1 定性 / P2 选型 ｜ 前置：[SKILL.md](../../SKILL.md) ｜ 后续：WS-02、WS-05、WS-06

## 🎯 适用场景

开发爬虫时遇到目标网站无法访问、返回 403/503、无限弹出验证码、返回的 HTML 是空壳，或者数据被篡改时，用本 SOP 系统化排查，避免"改一行试一次"的瞎撞。

## 🧠 核心心法（三大原则）

1. **遇事不决先侦察**：拒绝盲目修改代码。先收集证据——状态码、响应头、页面骨架、控制台报错、当前出口 IP、浏览器指纹特征——让 AI 帮你定性，再动手。
2. **拒绝重复造轮子，极限利用开源生态**：遇到反爬难题时，优先寻找高质量的开源项目（如修改底层协议的 patchright）和免费的社区资源；绝不轻易花钱购买商业代理或打码服务，靠技术手段（如请求降频、持久化上下文、开源的伪装脚本）来硬抗。
3. **不迷信一键开源**：GitHub 上的项目只当"技术思路库"。让 AI 提取核心逻辑，改写成能接进自己项目的胶水代码，比整包 `pip install` 稳妥得多。—— 这与上一条不冲突：**用开源是借力，整包照搬是偷懒。**

## 📋 标准化执行流程（SOP）

### 第一步：AI 辅助侦察（定性拦截层级）

先跑一个极简脚本，只做一件事：把证据打全。

- HTTP 状态码、`Content-Length`、关键响应头（`server`、`cf-ray`、`set-cookie`）
- 当前出口 IP（`https://api.ipify.org` 之类）
- 页面 body 的实际长度（**这是最容易被忽略的一项**：状态 200 但 body 只有几 KB，说明拿到的是空壳骨架，不是真数据）
- 浏览器指纹特征：WebGL renderer、Canvas hash、`navigator.webdriver`

**AI 提示词**

> 我使用 Playwright 访问目标网站，返回了 [状态码]，页面特征如下 [贴入响应片段]。请分析目标网站最可能使用了哪种反爬策略？是从 IP 层、TLS 指纹层、还是浏览器行为层拦截了我？

### 第二步：分层排查测试（寻找真相）

按 **成本从低到高** 的顺序试，每次只改一个变量：

1. **手动访问**：同机器、同网络、同浏览器手动打开。若手动也打不开，就是 **IP 封禁**，后面所有代码优化都无意义。
2. **排查矛盾参数**：去掉自己设的 UA、`timezone_id`、`locale`，用默认值再试。手工拼的 UA 与内核版本对不上，是最常见的自曝行为。
3. **有头 / 无头切换**：改 `headless=False`。若立刻成功，说明对方在查 Headless 特征。
4. **隔离行为**：只访问不点击。若"只看就被拦"，问题在浏览器指纹或网络层；若"一点击就拦"，问题在行为模拟（鼠标轨迹、点击间隔）。

> 补一条实测经验：**如果页面不是被拦，而是被切成 `about:blank`，或停在只有 logo 的 loading 骨架，那多半不是上面四层的问题，而是 CDP 级检测**——直接跳到 [02_cdp_detection_bypass.md](./02_cdp_detection_bypass.md)。

### 第三步：武器匹配与升级（精准打击）

| 目标防护等级 | 首选方案 | 说明 |
| --- | --- | --- |
| **常规反爬**（UA 校验、简单频率限制、非严格 JS 检测） | **Playwright + playwright-stealth** | 成本最低，够用就停，别过度武装 |
| **深度指纹检测**（Cloudflare / Akamai、Canvas + WebGL 指纹） | **Camoufox** | Firefox 基底，指纹面更干净，天然不像 Chromium 自动化 |
| **CDP 级检测**（页面被切成 `about:blank`、自动化绑定被扫到，如 **BOSS 直聘**） | **patchright + persistent context** | 具体做法见 → [02. 绕过 CDP 级检测实战](./02_cdp_detection_bypass.md) |
| **极高防护**（DataDome / Perimeter X / 风控天御） | **开源组合拳：Camoufox / patchright 深度调优 + 请求降频 + 自建代理池** | 不买商业代理与打码服务。先把节奏降到人一样的频率，多数风控在这一步就放过你了 |

### 第四步：GitHub 逆向工程（AI 辅助改写）

**错误做法**：把开源项目整个 clone 下来，装一堆编译依赖，跑不起来再逐个修。

**正确做法**：只找核心源码文件，让 AI 改写成独立函数。

**AI 提示词**

> 这是开源反爬项目的核心代码 [贴入代码片段]。请提取核心逻辑，改写成可无缝接入我现有 Playwright 项目的独立函数，并移除多余外部依赖。

### 第五步：工程化沉淀（构建基建）

跑通一次不算完。把可复用的部分抽成"请求中间件"，替换掉散落在业务代码里的临时补丁：

- 出口 IP 轮换（自建开源代理池，如 `proxy_pool`；或用手机热点、家宽重拨这类零成本手段）
- 请求重试（指数退避，区分"可重试的错误"和"重试也没用的封禁"）
- 随机延迟与节奏控制
- 登录态 / Cookie 的持久化与失效检测

## ⚠️ 避坑指南

- **依赖地狱**：遇到要装一堆 C++ 编译环境的开源项目，果断放弃。让 AI 改写核心逻辑，往往半小时就搞定了。
- **警惕投毒**：绝不在核心服务器上直接运行来源不明的开源脚本。先在隔离环境跑，看清它往外发了什么。
- **出口 IP 质量决定下限**：折腾三天指纹伪装，不如换一个干净的出口 IP（手机热点、家宽重拨、自建代理池）直接通。先怀疑 IP，再怀疑代码。
